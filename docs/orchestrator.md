# On-device decision logic (orchestrator)

For each 10 s Lead I window, the device runs:

```
int16 ADC window
  -> ExtractLead1Features             (firmware/ecg_features)
  -> AssessQuality  -- fails -->      report "unreliable" + reasons, skip the CNN
  -> RhythmFlags                      (always computed; cheap, interpretable)
  -> PrepareCnnInput (z-score, INT8)  written straight into the TFLM input tensor
  -> CNN callback (TFLM, Phase 2)  -> 5 probabilities -> DecideClasses
```

| | Python reference (spec) | C++ |
|---|---|---|
| Logic | `scripts/orchestrator.py` | `firmware/ecg_pipeline/ecg_pipeline.{h,cpp}` |
| Thresholds | `results/lead1/orchestrator_params.json` | `firmware/ecg_pipeline/ecg_pipeline_params.h` (generated by `orchestrator.py fit`) |
| Evaluation | `results/lead1/orchestrator_eval.md` | parity: `scripts/compare_pipeline.py` |

## How this differs from the README's original "hybrid" plan

The README planned to flag CD from the features and send only MI/HYP/STTC to a 3-lead CNN.
With Lead I hardware and the retrained models, the plan changed:

- **The Lead I CNN classifies all 5 superclasses whenever the window is clean.** It costs one
  ~25 KB INT8 inference per 10 s, and it beats the feature rules for CD. On the validation slice
  of the training folds, CD F1 was 0.658 for the CNN alone and 0.655 for the CNN OR wide-QRS rule,
  so `cd_or_wide_qrs` was fitted to `false`. The rule is still reported as a flag.
- **The features gate and explain.** The quality gate decides whether the CNN output can be
  trusted. The rhythm/interval flags give clinically readable findings (rate, irregularity, wide
  QRS, long PR) that the 5-class CNN does not output.

## Signal-quality gate

Each check sets a reason bit. Any set bit marks the window unreliable.

| Bit | Check | Threshold | Source |
|---|---|---|---|
| FLAT | peak-to-peak < 0.1 mV | fixed | lead off; the PTB-XL 0.1 % quantile is 0.27 mV |
| SATURATED | > 1 % of samples on an ADC rail | fixed | set `AdcInfo` to the real ADC range |
| NO_RHYTHM | < 4 R peaks, or mean HR outside 30–220 bpm | fixed | physiological range |
| NO_TEMPLATE | < 3 beats usable for the median beat | fixed | delineation needs it |
| NOISY | mean correlation of beats with the median beat < 0.598 | fitted: 2 % quantile on clean training windows | |
| BASELINE | Welch power < 0.5 Hz > 43 % of total | fitted: 99.5 % quantile on clean training windows | |

**Why template correlation instead of SNR.** PTB-XL marks noisy leads (`static_noise`,
`burst_noise`, `baseline_drift`), but none of the cheap indices separated those records
(training folds, `scripts/explore_quality_indices.py`):

| Index | AUC vs PTB-XL Lead I noise annotation |
|---|---:|
| `snr_db` | 0.504 |
| `baseline_wander` | 0.496 |
| raw std | 0.486 |

So the gate is validated with **real recorded noise added to clean windows**: the MIT-BIH Noise
Stress Test Database (`scripts/noise_stress.py`; baseline wander, electrode motion, muscle
artifact). The noise records are split in half. One half was used for exploration, the other for
the evaluation below.

## Results (fold 10, from `results/lead1/orchestrator_eval.md`)

**Clean windows.** 97.4 % pass the gate (57 of 2,158 rejected: 47 noisy, 14 baseline, 1 no
rhythm). Macro AUC is 0.8292 over all windows and 0.8303 over passed windows.

**Class decisions** use per-class thresholds that maximise F1 on the last 10 % of the training
folds (Keras' `validation_split`, never trained on). Macro F1 is **0.604**, against 0.515 with a
flat 0.5 threshold.

| Class | Threshold | F1 | Sensitivity | Specificity |
|---|---:|---:|---:|---:|
| CD | 0.24 | 0.589 | 0.534 | 0.919 |
| HYP | 0.24 | 0.423 | 0.462 | 0.902 |
| MI | 0.24 | 0.559 | 0.606 | 0.814 |
| NORM | 0.42 | 0.792 | 0.954 | 0.627 |
| STTC | 0.38 | 0.657 | 0.686 | 0.871 |

**Rhythm and interval flags vs PTB-XL statements (clean windows)**

| Flag | Rule | Reference | Sensitivity | Specificity | PPV |
|---|---|---|---:|---:|---:|
| TACHY | HR > 100 | STACH | 0.939 | 0.960 | 0.481 |
| BRADY | HR < 60 | SBRAD | 0.921 | 0.846 | 0.153 |
| IRREGULAR | RR CV ≥ 0.095 (Youden-fitted) | AFIB/AFLT | 0.905 | 0.868 | 0.333 |
| AF_SUSPECT | irregular and no P wave | AFIB/AFLT | 0.551 | 0.991 | 0.818 |
| WIDE_QRS | QRS ≥ 120 ms | 12SL QRS ≥ 120 ms | 0.776 | 0.964 | 0.652 |
| LONG_PR | PR > 200 ms | 1AVB | 0.380 | 0.946 | 0.211 |

Low PPVs for TACHY and BRADY are mostly a labelling effect. PTB-XL only codes STACH/SBRAD for
*sinus* rhythm, so tachycardic AF, for example, counts as a false positive. LONG_PR is weak because
Lead I PR reads ~24 ms shorter than 12SL (`docs/delineation.md`). A bias-corrected threshold of
~176 ms would be the next thing to try.

**Noise stress test (evaluation half of NSTDB)**

| Noise | SNR | Rejected | Macro AUC, all | Macro AUC, passed |
|---|---:|---:|---:|---:|
| electrode motion | +6 dB | 5.6 % | 0.812 | 0.814 |
| electrode motion | 0 dB | 20.6 % | 0.765 | 0.767 |
| electrode motion | −6 dB | 82.5 % | 0.653 | 0.694 |
| muscle | −6 dB | 43.0 % | 0.750 | 0.757 |
| baseline wander | −6 dB | 47.4 % | 0.786 | 0.801 |

The gate rejects more as noise grows, and the windows it passes score better than the full set.
The CNN tolerates baseline wander and muscle noise well. Electrode motion hurts it most, and the
gate rejects that noise most aggressively. At the 2 % clean-rejection budget, about 17 % of
windows still pass at −6 dB electrode motion, with AUC 0.694. A stricter gate trades clean-signal
availability for that. Revisit with recordings from the actual front end (Phase 3).

INT8 numbers use TFLite's reference kernels (`BUILTIN_REF`), which match TFLM on the RP2040
to within 1 output LSB (`docs/phase2_tflm.md`). With desktop XNNPACK the macro AUC was 0.8294.

## C++ parity (`scripts/compare_pipeline.py`)

3,778 windows: the 2,158 clean fold-10 windows, 1,600 noised copies and 20 flat windows.

| Output | Agreement |
|---|---|
| Quality bitmask | 100 % |
| Rhythm flags | 100 % |
| INT8 CNN input | 100 % of samples exact except one sample in one window (±1 LSB, rounding tie) |
| Class decisions | 100 % |
| Template correlation | max diff 2.6e-7 |

`PrepareCnnInput` computes the window mean and standard deviation from exact `int64` moments of
the ADC counts. It writes into a caller-supplied buffer, which on the device is the TFLM input
tensor, so it adds no SRAM beyond the arena.

## Re-fitting

```powershell
python scripts/orchestrator.py fit        # rewrites the JSON and ecg_pipeline_params.h
python scripts/orchestrator.py evaluate
g++ -std=c++14 -O2 -o build/pipeline_host.exe firmware/host_test/pipeline_main.cpp `
    firmware/ecg_pipeline/ecg_pipeline.cpp firmware/ecg_features/ecg_features.cpp
python scripts/compare_pipeline.py
```

When the CNN is retrained, re-run `fit`: the class thresholds belong to a specific model.

# Embedded Multi-Label ECG Diagnosis on the RAK11300 (RP2040)

Real-time detection of 5 cardiac superclasses on a RAK11300 module: a Raspberry Pi RP2040 (dual
Cortex-M0+, 133 MHz, 264 KB SRAM, no FPU) with an SX1262 LoRa radio. The ECG comes from a
3-electrode front end (RA, LA, RL), which gives **Lead I only**. The classes are Normal (NORM),
Myocardial Infarction (MI), ST/T Changes (STTC), Conduction Disturbance (CD) and Hypertrophy (HYP).

The design target is < 30 KB SRAM and < 50 KB flash for the ECG pipeline (`docs/sram_budget.md`).

## Setup

Python 3.13 with TensorFlow 2.21, scikit-learn, xgboost, scipy, wfdb, pandas, seaborn, and
nbclient/nbformat for headless runs. A C++14 compiler is needed for the host tests.

```powershell
# PTB-XL v1.0.3 -> dataset/ (records100/, ptbxl_database.csv, scp_statements.csv)
#   https://physionet.org/content/ptb-xl/1.0.3/
# PTB-XL+ 12SL features -> dataset/ptb-xl-plus/features/12sl_features.csv   (scripts/ptbxl_plus.py)
# MIT-BIH NSTDB -> dataset/nstdb/   (scripts/noise_stress.py)
python scripts/run_notebook.py --lead-set lead1 notebooks/01_preprocess.ipynb
python scripts/fix_cache.py                 # v1 features (used by the 3-lead baseline)
python scripts/build_lead1_features.py      # v2 Lead I features
```

`MTP_LEAD_SET=lead1|3lead` (or `run_notebook.py --lead-set`) selects which models a notebook
trains. The 3-lead baseline notebooks, with their original outputs, are at git tag `v0-3lead`.

## Status

### Done

- **Lead I retrain** (`docs/lead1_retrain.md`). Deployed INT8 1D-CNN: **macro AUC 0.829** on the
  fold-10 test set (3-lead float baseline: 0.8832). It is 25,184 B, and it matches the Lead I
  ResNet + attention ceiling (0.8310). Per-window z-score input keeps the INT8 loss under 0.001.
- **Working PR/QRS/QT** (`docs/delineation.md`). Lead I QRS separates CD as well as the 12-lead
  GE 12SL measurement (AUC 0.754 vs 0.755). Lead I XGBoost improves from 0.744 to 0.786.
- **C++ feature extraction** (`firmware/ecg_features`). It produces 18 features plus a signal-quality
  index, matches the Python reference on 21,387 of 21,388 PTB-XL windows, and uses a 5,780 B
  workspace.
- **Orchestrator** (`firmware/ecg_pipeline`, `docs/orchestrator.md`). The quality gate passes
  97.4 % of clean windows and rejects 83 % at −6 dB electrode-motion noise. Rhythm flags reach
  0.94 sensitivity for TACHY and 0.91 for IRREGULAR (vs AF). Class decisions reach macro F1 0.604.
  The C++ matches Python on all 3,778 test windows.
- **RP2040 build** (`firmware/rak11300_bench`). It builds with the Pico SDK 2.2.0 and a portable
  Arm GCC 15.3 kept in `.toolchain/`. ECG code plus model is 39,328 B of flash with no double
  arithmetic. The benchmark checks its own results against Python on the board.
- **TFLM on the RP2040** (`firmware/ecg_cnn`, `docs/phase2_tflm.md`). With no board available,
  the unmodified firmware ran on the rp2040js emulator. All 100 random test windows match Python
  end-to-end. The arena uses 20,788 B and the stack peaks at 1,636 B. Total pipeline SRAM is
  27.7 KB (target < 30 KB). Per 10 s window: CNN 175 ms, whole pipeline ~300 ms at 125 MHz.

## Corrections to earlier claims

The mid-term slides and the previous README contain numbers that no longer hold. Details are in
the linked documents.

- **Target device:** the target is the RAK11300 (RP2040), not an ESP32. "~520 KB SRAM" and
  "45 ms at 240 MHz" are ESP32 figures.
- **Lead count:** the 3-lead CNN cannot be fed by RA/LA/RL hardware. All deployable models are
  now Lead I.
- **"0.8626 macro AUC":** this was the Keras validation-split metric. On the test fold, the 3-lead
  CNN scores 0.8832 float and 0.8652 INT8.
- **"Mean_QRS > 120 ms isolates CD":** this came from a mislabeled plot that actually showed
  RR range. The original interval features did not work either (QT median 0.8 ms). Both are fixed;
  see `docs/delineation.md` and `results/features/lead1_justification.png`.
- **Model size and memory:** the old "~22 KB" is now 25,184 B for the Lead I INT8 model. The
  arena is 20,788 B (emulator-measured), and the TFLM runtime adds ~107 KB of flash on top.
- **"45 ms inference":** on the RP2040 at 125 MHz the CNN takes ~175 ms (emulator).
